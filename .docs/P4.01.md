# P4.01 — Runtime Session Provenance and Input Lock

Project version: **`4.0.0.0.0.0`**

Status: **Implementation complete — guest execution and real local session planning deferred**

## Objective

Create a deterministic, privacy-safe pre-execution record for every future VMApple runtime session.

P4.01 answers a specific problem left after P3.06: the integrated source contract can be correct while runtime evidence is still ambiguous if the QEMU binary or local guest inputs change between runs.

A P4.01 session plan therefore locks the runtime inputs before execution without copying or publishing them.

## Why this is separate from P1.09

P1.09 validates evidence manifests around real runs and enforces A/B comparability.

P4.01 is earlier in the lifecycle:

```text
P3.06 integrated contract
        ↓
P4.01 pre-execution plan
        ↓
future runtime execution
        ↓
P1.09 evidence manifest
        ↓
P1.10 promotion gate
```

The P4.01 plan is not accepted as runtime evidence.

## Role contracts

Probe:

```text
-M vmapple
-accel tcg
-cpu apple-gxf
```

Reference:

```text
host: Darwin arm64
-M vmapple
-accel hvf
-cpu host
```

The reference host restriction is deliberate. P4.01 refuses to create a reference-role plan on a host that is not Darwin/arm64.

## QEMU provenance

For the selected local QEMU executable, P4.01 records only sanitized provenance:

```text
basename
SHA-256
byte size
first version-output line
vmapple capability present
required accelerator present
required CPU model present
```

The full local executable path is not stored in the generated plan.

The capability checks use QEMU interfaces:

```text
-version
-machine help
-accel help
-cpu help
```

## Guest input lock

Required local inputs:

```text
firmware
AUX storage
root disk
compiled P3.02 machine identity
```

Optional:

```text
hardware model
```

For each file P4.01 stores only:

```text
sha256
bytes
```

No file is copied into the repository or `.build/` evidence output.

The machine-identity input is not merely hashed. The hardened runtime path requires the compiled P3.02 artifact, reproduces its `compiled_fingerprint`, verifies its machine ID, and later applies only its validated `vmapple-cfg.*` globals to QEMU.

## VMApple machine ID

The pinned VMApple machine property is named `uuid` in QEMU, but its source type is **`uint64_t`**. It feeds the VMApple config/SDOM/ECID path; it is not an RFC 4122/9562 128-bit UUID.

For compatibility with existing local scripts the environment variable remains:

```text
APPLESILICON_VMAPPLE_UUID
```

but its value must be a VMApple unsigned 64-bit machine ID, supplied either as decimal or `0x`-prefixed hexadecimal.

P4.01 canonicalizes the value to unsigned decimal ASCII, hashes that canonical text with SHA-256, and stores only:

```text
sha256
normalized_bytes
encoding = uint64_decimal
semantic = vmapple_sdom_ecid
raw_value_stored = false
```

No 128-bit UUID parser or 128→64 conversion is used.

The compiled P3.02 identity must contain the same machine ID. A mismatch fails before QEMU is allowed to run.

## P3.06 prerequisite

The supplied P3.06 manifest must contain the expected closed integration state and its `platform_integration_fingerprint` must **reproduce from the supplied document**. A value that merely looks like 64 hexadecimal characters is not trusted.

This prevents a session from being planned against a stale or manually edited CPU/platform state.

## Trace contract

P4.01 keeps the Part 01 trace contract unchanged:

```text
memory_region_ops_read
memory_region_ops_write
```

with debug items:

```text
guest_errors
unimp
int
cpu_reset
```

## Determinism and authentication

`plan-p4.01-session.sh` invokes the session planner twice with the same inputs and requires byte-for-byte identical JSON output.

The plan deliberately contains no timestamp, PID, hostname or absolute local path so that those runtime-host details cannot make the provenance fingerprint nondeterministic.

The final plan contains:

```text
session_fingerprint = SHA-256(canonical plan content)
```

The hardened planner also exposes `validate-plan`, which recomputes the fingerprint from the supplied JSON before any later runtime stage may consume it.

## Privacy rules

The plan must not contain:

- raw local paths;
- hostname;
- raw VMApple machine ID;
- machine-identity content;
- hardware-model content;
- firmware/AUX/disk content;
- real serial/account identifiers.

A QEMU basename is permitted as a human-readable binary label; the executable SHA-256 remains the actual identity.

## Files

```text
.src/.configs/p4.01-runtime-session-policy.json
.src/.tools/runtime_integrity.py
.src/.tools/runtime-session.py
.src/.tools/prepare-p4.01.sh
.src/.tools/plan-p4.01-session.sh
```

`runtime_integrity.py` centralizes the uint64 machine-ID, compiled-identity and generated-fingerprint checks shared by the later runtime layers.

`prepare-p4.01.sh` performs source-free/static policy validation and negative self-checks while writing a persistent `.log`.

`plan-p4.01-session.sh` is the later local pre-execution path. It requires a real P3.06 manifest, QEMU executable and local VM inputs, creates the plan twice, authenticates the result, and performs the determinism/privacy checks. It also writes a persistent `.log`.

## No emulator patch

P4.01 adds no Inferno/QEMU patch. The patch chain remains exactly `0001` through `0005`.

## Runtime status

P4.01 itself launches no guest.

No macOS boot, TCG session, HVF session or m1n1 session is claimed by this objective.
