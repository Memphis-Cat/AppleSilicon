# P4.04 — Comparable A/B Session Assembly

Project version: **`4.3.0.0.0.0`**

Status: **Implementation complete — real A/B assembly deferred until P4.02/P4.03 captures exist**

## Purpose

P4.04 is the admission gate between provenance-bound runtime captures and later trace-divergence analysis.

It does not launch QEMU, compare traces, or promote a divergence. It proves that one P4.03 Apple-Silicon/HVF reference observation and one P4.02 TCG/`apple-gxf` probe observation were produced under a sufficiently identical contract to be compared.

## Inputs

P4.04 requires six local sanitized artifacts:

```text
P4.01 reference session plan
P4.01 probe session plan
P4.03 reference capture descriptor
P4.02 probe capture descriptor
P1.09 reference manifest
P1.09 probe manifest
```

The original session plans are required so P4.04 can compare provenance fields that are deliberately absent from the closed P1.09 manifest format, especially the hashed machine UUID and exact planned QEMU provenance.

## Equality contract

The reference and probe plans must agree on:

```text
P3.06 manifest SHA-256
P3.06 platform integration fingerprint
machine UUID SHA-256
guest input hashes and sizes
trace/debug contract
locked project artifacts
QEMU version string
```

The P1.09 manifests independently require equality for pinned Inferno source, VMApple machine, RAM/SMP, trace events/debug items and guest-input hashes/sizes.

The runtime geometry is fixed at:

```text
RAM   4096 MiB
SMP   4
```

## Intentional differences

The following role differences are expected and are not compatibility failures:

```text
reference host vs probe host
HVF vs TCG
host CPU vs apple-gxf
QEMU executable SHA-256/byte size across host builds
role-specific session fingerprint
```

The QEMU binary digest is allowed to differ because the two hosts may require different executable builds. The QEMU version string must still match.

## Capture binding

P4.04 recomputes each P4.02/P4.03 capture fingerprint and requires each capture to bind:

- its exact P4.01 session fingerprint;
- the exact P3.06 platform fingerprint;
- the same guest-input digest set;
- the same trace/debug contract;
- the exact supplied P1.09 manifest SHA-256 and run ID.

A renamed, swapped or edited manifest cannot be silently paired with a capture descriptor.

## P1.09 remains authoritative

P4.04 invokes:

```text
reference-manifest.py compare
```

using the existing P1.09 manifest policy. A non-comparable P1.09 pair is rejected rather than normalized away.

P4.04 adds only the provenance checks P1.09 cannot perform because the older manifest intentionally does not store fields such as the machine UUID digest or QEMU executable digest.

## Deterministic output

`.src/.tools/assemble-p4.04.sh` assembles the same pair twice and requires byte-for-byte identical output.

The final local artifact is:

```text
.build/p4.04/ab-session.json
```

with classification:

```text
P4_04_AB_SESSION_READY
```

and a deterministic `ab_fingerprint`.

The bundle contains sanitized digests/metadata only. It stores no raw local paths, raw UUID, firmware contents, disk contents, machine-identity contents, hardware-model contents, credentials, keys or tickets.

## Evidence boundary

`P4_04_AB_SESSION_READY` means only:

```text
reference + probe are admissible as one A/B pair
```

It does **not** mean:

```text
macOS booted successfully
TCG matches Apple Silicon
a divergence exists
a divergence was reproduced
a compatibility behavior should be implemented
```

P1.08 remains authoritative for trace comparison and P1.10 remains authoritative for divergence promotion.
