# P2.06 — Part 02 Integration Gate

Project version: **`2.5.0.0.0.0`**

Status: **Implementation complete — Part 02 closed**

## Objective

P2.06 binds the completed Part 02 CPU compatibility component to the Part 01 VMApple/TCG probe and evidence pipeline without launching a macOS guest during development.

The integration contract is:

```text
machine      = vmapple
accelerator  = tcg
CPU          = apple-gxf
control CPU  = max
```

P2.06 does not add another CPU behavior patch.

## Integration policy

P2.06 adds:

```text
.src/.configs/p2.06-integration-policy.json
```

It requires:

- the exact pinned Inferno revision;
- a passing P2.05 deterministic CPU regression;
- the full patch series to apply cleanly;
- `max` to remain free of AppleSilicon compatibility hooks;
- TCG `apple-gxf` to contain both the feature-profile and sysreg-framework hooks;
- P2.03's live Apple implementation-defined sysreg policy count to remain zero;
- P1.07 to remain the runtime probe instead of creating a competing boot harness;
- P1.09 and P1.10 to remain the evidence and promotion gates;
- guest execution to remain deferred during objective development.

## Deterministic integration manifest

P2.06 adds:

```text
.src/.tools/integration-gate.py
```

The tool validates locked artifact Git blob identities, consumes a passing P2.05 regression result, inspects the fully patched source tree, and emits:

```text
.build/p2.06/integration-manifest.json
```

The manifest contains only deterministic integration state, including:

```text
P2.05 suite fingerprint
locked artifact hashes
pinned Inferno revision
ordered patch hashes
CPU/machine/accelerator contract
max-control isolation state
apple-gxf TCG wiring state
live sysreg policy count
Part 02 closure state
```

It also emits a SHA-256 `integration_fingerprint` over the deterministic manifest basis.

No timestamps, hostnames, local firmware paths, UUIDs or Apple VM identity material are included.

## Preparation harness

P2.06 adds:

```text
.src/.tools/prepare-p2.06.sh
```

The logged harness:

1. validates the pinned Inferno source;
2. runs P2.05 in an isolated P2.06 work directory;
3. requires the P2.05 regression result to exist and pass;
4. clones the exact Inferno pin into `.build/p2.06/inferno-src`;
5. applies patches `0001` through `0005` in order;
6. requires `git diff --check` to pass;
7. generates the P2.06 integration manifest twice;
8. requires the two manifests to be byte-identical;
9. validates the Part 02 closure and Part 03 transition fields;
10. writes a persistent `.log`.

Every run writes:

```text
.logs/AppleSilicon-p2.06-YYYYMMDD-HHMMSS-PID.log
```

## Final runtime wrapper

P2.06 also adds:

```text
.src/.tools/run-p2.06-probe.sh
```

This script is intentionally a wrapper around P1.07 rather than a second independent launch implementation.

Before delegation it requires:

```text
P2.06 integration manifest = PASS
Part 02 state              = closed
machine capability         = vmapple
accelerator capability     = tcg
CPU capability             = apple-gxf
```

It then forces:

```text
APPLESILICON_VMAPPLE_ACCEL=tcg
APPLESILICON_VMAPPLE_CPU_PROFILE=apple-gxf
```

and delegates the actual observational launch to `run-p1.07-probe.sh`.

The wrapper explicitly validates QEMU capabilities, not binary build provenance. A future integrated build/test stage must record the exact binary provenance separately before making empirical claims.

## Evidence flow remains unchanged

A P2.06 runtime result does not automatically become a confirmed CPU requirement.

The flow remains:

```text
P2.06 capability-gated probe
        |
        v
P1.07 runtime evidence
        |
        v
P1.09 paired manifest contract
        |
        v
P1.08 normalized comparison
        |
        v
P1.10 reproducibility/promotion gate
```

Therefore a crash, exception, timeout or different MMIO trace is observational evidence only until the existing promotion requirements are satisfied.

## What P2.06 proves

P2.06 proves that the Part 02 CPU component can be assembled deterministically with the Part 01 VMApple/TCG experiment contract as source/configuration state.

It proves the following integration invariants are enforced:

```text
vmapple + TCG + apple-gxf
max remains control CPU
P2.03 unknown sysreg semantics remain fail-closed
P2.04 architectural minimum profile remains attached
P2.05 deterministic regression must pass
Part 01 evidence gates remain authoritative
```

It does **not** prove macOS boots, that an Apple M-series CPU is emulated, that paravirtualized PAC is complete, or that any currently unknown Apple implementation-defined register semantic is required.
