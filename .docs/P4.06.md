## Runtime evidence gate

The runtime evaluator requires at least two independent P4.04-admitted A/B sessions. It reuses P4.05's A/B validation and independence rules, then regenerates a P1.10 candidate from the exact manifests/traces of every reproduction.

The reference remains:

```text
vmapple / HVF / host / Darwin arm64
```

The probe remains:

```text
vmapple / TCG / apple-gxf
```

with 4096 MiB RAM and 4 vCPUs.

### Outcome A — equivalent observations

Every independent reproduction must produce a runtime-origin P1.10 candidate with:

```text
status = no_divergence
```

The resulting classification is:

```text
P4_06_RUNTIME_EVIDENCE_PASS_EQUIVALENT_OBSERVATIONS
```

This only means no canonical divergence was observed within the configured P1.08 trace contract and capture window. It is not proof of a full macOS boot or complete hardware equivalence.

### Outcome B — reproducible promoted divergence

Every independent reproduction must produce the same runtime divergence signature and P1.09 contract fingerprint.

A P4.05 record is mandatory and must reproduce exactly, bind the same A/B sessions, and show P1.10 promotion:

```text
P01-DIVERGENCE-0001
status = promoted
auto_committed = false
```

The resulting classification is:

```text
P4_06_RUNTIME_EVIDENCE_PASS_PROMOTED_DIVERGENCE
```

A promoted divergence is evidence for investigation. P4.06 does not automatically convert it into a sysreg, device, crypto, graphics or other hardware requirement.

## Rejected states

P4.06 rejects:

- fewer than two independent A/B sessions;
- reused reference/probe runs or capture fingerprints;
- mixed `no_divergence` and `divergence_candidate` outcomes;
- mismatched P1.09 contract fingerprints;
- mismatched divergence signatures;
- a divergence without the exact P4.05 promotion record;
- a promotion record with P1.10 auto-commit enabled;
- a changed P4.01–P4.05 policy/tool lock;
- any new compatibility patch after `0005`;
- root README drift;
- a fabricated runtime pass when evidence is missing.
