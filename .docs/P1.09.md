# P1.09 — Reference Trace Manifest and Real-Hardware Trace Preparation

Project version: **`0.9.0.0.0.0`**

Parent: **Part 01 — VMApple Baseline and Host-Dependency Map**

Status: **Implementation complete — real reference/probe collection deferred**

## Objective

P1.09 defines exactly what evidence is allowed to participate in the first real VMApple reference/probe comparison.

P1.08 can already normalize MMIO traces and report their earliest difference. That is only useful if the two traces are actually comparable.

P1.09 therefore creates a machine-checkable evidence contract for:

```text
A — reference
    QEMU VMApple
    Apple Silicon macOS host
    HVF
    CPU model host

B — probe
    QEMU VMApple
    TCG
    explicit max or apple-gxf CPU model
```

The two runs may differ in host, accelerator, and CPU model. They must not silently differ in the pinned emulator revision, VMApple machine shape, memory/SMP configuration, trace event set, debug set, or local guest inputs.

No real VM is launched by the P1.09 preparation/self-check path.

## Why the primary reference is VMApple/HVF

QEMU documents VMApple as its independent implementation of the device model that Apple's Virtualization.framework exposes to Apple Silicon macOS guests.

Primary source:

- <https://www.qemu.org/docs/master/system/arm/vmapple.html>

That makes the cleanest first differential experiment:

```text
same VMApple device model
same guest inputs
same trace contract

reference CPU path: Apple host + HVF
probe CPU path:     explicit non-host CPU + TCG
```

m1n1 is intentionally not substituted for the primary A-side trace because m1n1 is a different hypervisor/tracing environment running against real Apple hardware.

## Apple VM identity metadata

Apple's Virtualization framework models macOS platform identity using objects including:

```text
VZMacHardwareModel
VZMacMachineIdentifier
VZMacAuxiliaryStorage
```

Apple describes the hardware model as the virtualized hardware configuration used for a Mac VM and the machine identifier as a unique identifier for a virtual Mac hardware instance.

Primary sources:

- <https://developer.apple.com/documentation/virtualization/vzmachardwaremodel>
- <https://developer.apple.com/documentation/virtualization/vzmacmachineidentifier>
- <https://developer.apple.com/documentation/virtualization/running-macos-in-a-virtual-machine-on-apple-silicon>

The raw serialized hardware-model and machine-identifier data are not repository metadata.

P1.09 records only:

```text
SHA-256
byte size
```

for local identity/input files.

This lets two runs prove they used the same local material without publishing the material itself.

## Versionable manifest

Every versionable P1.09 manifest has:

```text
schema
project_version
role
run
source
host
machine
command
trace
guest_inputs
artifacts
sanitization
reference_escalation
```

### Role

Allowed roles are:

```text
reference
probe
```

The policy enforces:

```text
reference:
    accelerator = hvf
    cpu_model   = host

probe:
    accelerator = tcg
    cpu_model   = max | apple-gxf
```

A manifest with the wrong role/CPU/accelerator combination is rejected before trace comparison.

## Pair-equality contract

Before P1.08 is allowed to compare real traces, P1.09 requires equality for:

```text
source.repository
source.revision
machine.type
machine.ram_mib
machine.smp
trace.events
trace.debug_items
guest firmware SHA-256 + size
auxiliary-storage SHA-256 + size
disk SHA-256 + size
machine-identity SHA-256 + size
hardware-model digest metadata when available
```

Host metadata is recorded but does not need to match.

The following differences are expected and explicit:

```text
reference accelerator: hvf
probe accelerator:     tcg

reference CPU: host
probe CPU:     max or apple-gxf
```

If any equality field differs, the pair is **not comparable**. It must not be passed to the real-divergence promotion step merely because the traces happen to differ.

## Privacy policy

A versionable P1.09 manifest must not contain:

```text
raw VM UUID
raw machine identifier
raw hardware-model serialization
Apple ID / email address
passwords
credentials/tokens
private keys
signing tickets
APFS keys
hardware serial number
hardware UUID
local user-home paths
```

The validator rejects UUID-like values, account-like email strings, private-key markers, common local user-home paths, and configured sensitive key names.

The redacted command shape must identify VMApple while using:

```text
uuid=<redacted>
```

The local collector hashes files in place and writes only hash/size metadata and artifact basenames into the manifest. It does not copy firmware, disk images, auxiliary storage, identity data, or trace contents into the repository.

## Artifact records

Generated evidence can be recorded as:

```text
launcher_log
serial_log
qemu_debug_log
trace_capability_log
normalized_trace
manifest_log
hardware_trace_log
hardware_trace_metadata
```

Each versionable artifact record contains:

```text
kind
label (basename only)
sha256
bytes
```

The actual raw evidence remains under ignored local paths such as `.logs/` and `.build/` unless a deliberately sanitized fixture is created.

## P1.09 manifest tool

P1.09 adds:

```text
.src/.tools/reference-manifest.py
```

Commands:

```text
validate
compare
collect
self-check
```

### validate

Checks one manifest against:

```text
schema
project version
pinned Inferno revision
role/accelerator/CPU contract
VMApple machine type
time metadata
trace requirements
digest formatting
artifact types
privacy rules
sanitization declarations
```

### compare

Validates a reference and probe manifest, then checks every configured pair-equality field.

Return behavior:

```text
0   pair is comparable
10  pair is valid individually but violates the pairing contract
2   malformed/unsafe input
```

The report identifies expected host/CPU/accelerator differences separately from accidental contract differences.

### collect

Hashes local inputs/artifacts and emits a sanitized manifest.

The collector never embeds the source file paths in the output. Artifact records contain only the basename plus digest metadata.

### self-check

Uses temporary synthetic files to prove:

```text
valid reference accepted
valid probe accepted
matching A/B pair accepted
changed disk hash rejected as non-comparable
raw UUID rejected
missing required trace event rejected
```

No guest or emulator is launched.

## HVF reference runner

P1.09 adds:

```text
.src/.tools/run-p1.09-reference.sh
```

This runner is reserved for the final integration evidence stage.

It fails closed unless the host reports:

```text
Darwin
arm64
```

It then requires the same local VMApple input classes used by the probe path and verifies:

```text
vmapple machine advertised
HVF accelerator advertised
configured trace events available
```

The intended runtime shape is:

```text
qemu-system-aarch64
    -accel hvf
    -cpu host
    -M vmapple,uuid=<local value>
    same RAM/SMP contract
    same firmware
    same auxiliary storage
    same disk
    same MMIO trace set
    same debug categories
```

It writes persistent local logs and, after a completed/finite reference execution, invokes the P1.09 collector to produce a sanitized local reference manifest.

The command line printed in metadata is redacted.

P1.09 does not ask the project owner to execute this runner now.

## m1n1 escalation path

m1n1 is used only if a future reference/probe mismatch reaches Apple behavior that cannot be explained confidently from:

```text
QEMU / Inferno source
Apple open-source XNU
Apple public documentation
existing project evidence
```

Asahi documents m1n1's hypervisor as capable of running XNU/macOS and preloading Python tracer modules for real-time hardware tracing.

Primary sources:

- <https://asahilinux.org/docs/sw/m1n1-hypervisor/>
- <https://asahilinux.org/docs/sw/m1n1-user-guide/>

At the time P1.09 was written (2026-08-11), the Asahi hypervisor documentation listed pinned targets including macOS 13.5 for M1/M2 and macOS 14.8.3 for M1–M3, while noting no pinned M4-and-newer target yet.

That support matrix is **not** treated as permanent project truth. Any actual future hardware trace must record:

```text
m1n1 revision
target macOS version
hardware family
tracer-module SHA-256
trace time/run identifier
which observed register/device behavior is being investigated
```

m1n1 evidence is secondary evidence. It must not be mechanically diffed against a VMApple trace as though both environments were the same device model.

If the macOS version/hardware generation differs from the VMApple baseline, the interpretation must explicitly account for that difference.

## Safety of real-hardware preparation

P1.09 does not automate:

```text
Secure Enclave extraction
Activation Lock bypass
account-security bypass
signing-ticket extraction
private-key extraction
DFU manipulation
boot-policy circumvention
```

It also does not commit Apple firmware, restore images, kernelcaches, KDK binaries, macOS disks, or private hardware traces automatically.

Any future real-hardware session must use hardware the researcher is authorized to test and preserve raw evidence locally unless a sanitized subset is deliberately prepared.

## Development-side validation

P1.09 adds:

```text
.src/.tools/prepare-p1.09.sh
```

The preparation harness:

1. validates all P1.09 JSON,
2. syntax-checks the Python manifest tool without creating Python cache files,
3. syntax-checks the HVF reference runner,
4. runs the manifest self-check,
5. validates the reference/probe example manifests,
6. verifies they satisfy the pairing contract,
7. exercises the collector against temporary synthetic local files,
8. validates the collected output,
9. writes a persistent `.log`.

It does **not** launch QEMU, macOS, HVF, or m1n1.

## Acceptance conditions

P1.09 implementation is complete when:

1. reference and probe roles are explicit and machine-validated,
2. the pinned Inferno revision is part of every manifest,
3. same-input equality can be proven by hash without publishing guest inputs,
4. accidental RAM/SMP/trace differences make a pair non-comparable,
5. raw UUID/account/private-key/local-user-path material is rejected,
6. a local collector can generate a sanitized manifest from local inputs and logs,
7. the controlled HVF reference runner is defined and fail-closed to Apple Silicon macOS,
8. m1n1 is documented as a secondary escalation path rather than a fake A/B substitute,
9. deterministic synthetic validation passes without guest execution,
10. no maintainer runtime test is required at this objective.

## Not completed by P1.09

P1.09 does not:

- produce a real HVF reference trace yet,
- produce a real TCG trace yet,
- claim those traces diverge,
- assign `P01-DIVERGENCE-0001`,
- implement the behavior behind a future divergence,
- make m1n1 traces equivalent to VMApple traces,
- alter XNU or Apple firmware.
