# P3.03 — Interrupt, Timer, Power and Console Contract

Project version: **`3.2.0.0.0.0`**

Status: **Implementation complete — guest/runtime interrupt validation intentionally deferred**

## Objective

Freeze the VMApple interrupt, architectural timer, power-input, console and diagnostic contract without replacing generic QEMU devices that already match the reference VMApple machine.

P3.03 owns the P3.01 components:

- `gicv3`
- `architectural_virtual_timer`
- `pl011_uart`
- `pl031_rtc`
- `pl061_gpio_power`
- `pvpanic_mmio`

It does not own CPU feature/sysreg behavior, VMApple identity, boot storage, PCIe, AES or graphics.

## Source result

Pinned Inferno and upstream QEMU 11.1.0 expose the same guest-visible VMApple wiring for the P3.03 devices.

No P3.03 source patch is therefore justified.

The project preserves the existing generic QEMU devices and validates their placement/wiring instead.

## GICv3 contract

VMApple creates a standalone generic GICv3.

```text
Distributor:
base  0x10000000
size  0x00010000

Redistributors:
base  0x10010000
size  0x00400000
```

The machine configures:

```text
revision       3
external IRQs  256
internal IRQs   32
num-irq        288
num-cpu        MachineState.smp.cpus
```

XNU's public VMApple platform configuration independently defines:

```text
HAS_GIC_V3 = 1
GICR_PE_SIZE = 0x20000
```

The VMApple redistributor window is `0x400000` bytes.

With a `0x20000` per-PE stride:

```text
0x400000 / 0x20000 = 32
```

That exactly matches VMApple's machine-class maximum of 32 CPUs.

For every realized vCPU, QEMU connects the GIC IRQ/FIQ outputs to:

```text
ARM_CPU_IRQ
ARM_CPU_FIQ
```

P3.03 treats those values as part of the reference machine contract.

## Architectural virtual timer

For each CPU, VMApple connects:

```text
GTIMER_VIRT -> GIC PPI 27
```

P3.03 freezes PPI 27 as the VMApple reference wiring.

This is an architectural Arm timer path, not an Apple implementation-defined timer device.

No Apple timer emulation is added.

## PL011 console

VMApple maps the generic PL011 at:

```text
base  0x20010000
size  0x00010000
SPI   1
```

and connects it to `serial_hd(0)`.

XNU's VMApple configuration explicitly selects:

```text
PL011_UART
```

This makes PL011 a source-backed VMApple guest contract rather than a compatibility guess.

P3.03 therefore preserves the generic QEMU PL011 implementation.

## PL031 RTC

VMApple maps the generic PL031 RTC at:

```text
base  0x20050000
size  0x00001000
SPI   2
```

This is source-backed as part of the reference VMApple machine, but P3.03 does not claim that a particular wall-clock value or host-time relationship is boot-critical.

The generic device is preserved.

## PL061 GPIO and power request

VMApple maps a generic PL061 at:

```text
base       0x20060000
size       0x00001000
SPI        5
pullups    0x00
pulldowns  0xff
```

A generic `gpio-key` device is connected to PL061 pin 3.

A QEMU powerdown request drives input 0 of that key device high.

The wiring is source-backed. The exact guest-observable event semantics are not yet proven by an A/B runtime trace.

P3.03 therefore records:

```text
event_semantics = unknown_requires_runtime_evidence
```

It does not invent pulse duration, edge behavior, deassert timing or macOS policy.

## pvpanic

VMApple maps the generic MMIO pvpanic device at:

```text
base  0x20070000
size  0x00000002
IRQ   none
```

P3.03 preserves it as an optional diagnostic/reference component.

Its presence is not promoted to a macOS boot requirement.

## Upstream comparison

P3.03 source-locks upstream QEMU 11.1.0 commit:

```text
84f07211cc5b4fc6a371559bf8a5de4fb068e648
```

with VMApple source blob:

```text
607181f5177b1c798a7504150ce29aa383b29993
```

The relevant address map and wiring remain consistent with pinned Inferno.

That comparison is evidence against introducing a fork-specific replacement for these devices.

## Machine-readable contract

P3.03 adds:

```text
.src/.configs/p3.03-io-contract.json
```

It records:

- exact source locks;
- machine/GIC limits;
- guest-visible MMIO addresses;
- external IRQ numbers;
- virtual timer PPI;
- GIC CPU-line wiring;
- power GPIO wiring;
- source-backed versus reference-only requirements;
- the unresolved power-event semantics.

## Validation tooling

P3.03 adds:

```text
.src/.tools/platform-io-contract.py
.src/.tools/prepare-p3.03.sh
```

`platform-io-contract.py` provides:

```text
validate
summary
self-check
verify-source
```

The validator rejects, among other things:

- changed GIC distributor/redistributor geometry;
- a redistributor capacity different from the 32-vCPU VMApple cap;
- a changed virtual-timer PPI;
- changed UART/RTC/GPIO interrupt IDs;
- promotion of pvpanic to a boot requirement;
- invented power-button event semantics;
- reclassification of these generic devices as VMApple-specific without evidence;
- Inferno/XNU/QEMU source-lock drift;
- Part 03 scope creep to P3.07.

`prepare-p3.03.sh` performs logged non-guest validation against the exact pinned Inferno source and emits deterministic summaries beneath:

```text
.build/p3.03/
```

Every meaningful run writes:

```text
.logs/AppleSilicon-p3.03-YYYYMMDD-HHMMSS-PID.log
```

## Source-patch decision

P3.03 adds **no new Inferno patch**.

The result is:

```text
generic device exists
        +
reference wiring is stable
        +
XNU confirms GICv3/PL011
        ↓
preserve + validate
```

not:

```text
generic device
        ↓
replace because it is not Apple-specific
```

A later patch is justified only if runtime evidence proves a concrete incompatibility.

## Testing boundary

The contract/tool self-checks are development-side static validation.

No macOS guest, HVF VM or TCG VM is claimed to have been run for P3.03.

The exact power-event behavior and guest-visible interrupt timing remain empirical questions for final integrated testing.

## Result

P3.03 establishes the deterministic VMApple IRQ/timer/power/console baseline without adding speculative platform emulation.
