# P2.05 — Deterministic CPU Contract Regression Harness

Project version: **`2.4.0.0.0.0`**

Status: **Implementation complete — deterministic non-guest regression**

## Objective

P2.05 turns the Part 02 CPU contract into one repeatable regression suite.

The objective is:

> Prove that the source-locked P2.01 inventory, P2.02 fail-closed sysreg framework, P2.03 semantic policy model, and P2.04 architectural feature profile still agree with each other and with the exact ordered Inferno patch set before Part 02 integration.

P2.05 does not launch macOS or claim CPU compatibility from a guest boot.

## Why this is separate from P2.06

P2.05 tests the CPU compatibility subsystem as a component.

P2.06 is the final Part 02 integration gate and will connect that component to the prepared VMApple/TCG path from Part 01.

Keeping those stages separate prevents an integration failure from being confused with a CPU-contract regression.

## Files

P2.05 adds:

```text
.src/.configs/p2.05-regression-policy.json
.src/.tools/cpu-contract-regression.py
.src/.tools/prepare-p2.05.sh
```

No new CPU behavior patch is introduced by P2.05.

## Locked regression inputs

The regression policy locks the exact Git blob identities of:

```text
P2.01 CPU inventory
P2.02 sysreg framework policy
P2.03 sysreg semantic policy
P2.04 feature contract
0003 sysreg framework patch
0004 sysreg policy patch
0005 VMApple feature profile patch
```

A byte-level change to one of those artifacts is therefore an explicit regression-input change rather than silent drift.

The tool calculates Git blob IDs locally using the canonical Git `blob <size>\0<bytes>` representation and also records SHA-256 hashes in the regression result.

## Cross-objective invariants

The regression suite checks that:

- P2.01 → P2.02 → P2.03 → P2.04 sequencing is unchanged;
- P2.02 and P2.03 remain scoped to `apple-gxf` + TCG;
- `max` remains the untouched control CPU;
- every P2.02 representative register still matches its exact P2.01 group and architectural encoding;
- P2.02 unresolved behavior remains `CP_ACCESS_UNDEFINED`;
- unresolved reads, writes and resets are not invented;
- P2.03 still has zero live evidence-promoted implementation-defined sysreg policies;
- P2.03 still requires undefined behavior for unknown reads/writes;
- P2.04 still contains the exact architectural requirement set;
- every P2.04 requirement remains `enforced`;
- P2.04 still uses the minimum/preserve-stronger rule;
- P2.04 still leaves sysreg semantics owned by P2.03;
- the P2.01 and P2.04 Inferno source locks agree.

## Prepared-source invariants

`prepare-p2.05.sh` creates a disposable source tree from the exact pinned Inferno revision and applies patches `0001` through `0005`.

The regression tool then verifies the resulting source directly.

It checks that:

```text
max:
  no Apple feature-profile hook
  no Apple sysreg-framework hook

apple-gxf under TCG:
  apple_cpu_feature_profile_init(cpu)
  apple_sysreg_framework_init(cpu)

Apple sysreg framework:
  live_policy_count = 0

Apple architectural profile:
  PAuth postcondition
  SSBS2 minimum
  SME2 minimum
  PAN3 minimum
  16K granule support
  range TLBI support
```

The Meson build wiring for both project-owned CPU files is checked as well.

## Deterministic result

The canonical output is:

```text
.build/p2.05/cpu-contract-regression.json
```

It contains no timestamps, hostnames, user paths, random IDs or runtime counters.

The result contains:

```text
classification
policy SHA-256
locked artifact Git blob IDs
locked artifact SHA-256 hashes
cross-contract summary
prepared-source invariant summary
suite fingerprint
guest_execution = false
```

The suite fingerprint is SHA-256 over canonical JSON containing only deterministic regression inputs/results.

`prepare-p2.05.sh` runs the regression twice against the same prepared source and requires the two JSON files to be byte-identical.

## Negative self-checks

`cpu-contract-regression.py self-check` deliberately mutates copies of policy/contracts and verifies they are rejected.

The self-check covers at least:

```text
CPU scope drift
disabled mandatory invariant
missing locked artifact
locked blob mismatch
representative register encoding drift
unapproved live Apple sysreg policy
unenforced P2.04 feature requirement
nondeterministic regression output
```

These mutations never modify repository files.

## Logging

Every preparation run writes:

```text
.logs/AppleSilicon-p2.05-YYYYMMDD-HHMMSS-PID.log
```

The log records the stage, classification, exit code, source revision and final regression fingerprint.

## QEMU testing model

QEMU's own testing documentation separates unit/component validation from full functional guest testing. P2.05 follows that model: deterministic CPU-contract validation is performed now, while full VMApple/macOS execution remains a later integration concern.

## What P2.05 proves

P2.05 proves that the current Part 02 CPU-contract implementation is internally consistent and reproducible as source/configuration state.

It does **not** prove:

- that macOS reaches XNU under TCG;
- that any Apple implementation-defined sysreg is required;
- that paravirtualized PAC is complete;
- that VMApple's interrupt/platform/device contracts are complete;
- that an M-series CPU is emulated.

## Guest status

No guest execution is claimed for P2.05.

## Exit criteria

P2.05 is implementation-complete when:

1. all Part 02 contract inputs are content-locked;
2. cross-objective invariants are machine-checked;
3. the exact patch series is applied to a disposable pinned Inferno source tree;
4. prepared-source CPU invariants are machine-checked;
5. negative mutation self-checks exist;
6. two identical runs produce byte-identical canonical regression JSON;
7. every meaningful run writes a `.log`;
8. no guest execution is required.
