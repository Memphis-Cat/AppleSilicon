# P4.05 — Reproducible Divergence Promotion

Project version: **`4.4.0.0.0.0`**

Status: **Implementation complete — real reproduced runtime divergence promotion deferred**

## Objective

P4.05 connects admitted P4.04 A/B runtime sessions to the existing P1.08 trace comparator and P1.10 reproduction/promotion gate without creating a second promotion algorithm.

The objective answers one question:

> Has the same earliest normalized runtime divergence been reproduced by at least two genuinely independent, otherwise equivalent A/B observations?

P4.05 does not launch QEMU and does not create an emulator patch. It consumes completed runtime evidence from P4.02–P4.04.

## Authority boundary

Part 01 remains authoritative:

```text
P1.08  trace normalization/comparison
P1.09  reference/probe comparability
P1.10  candidate generation and promotion
```

P4.05 only strengthens provenance around those mechanisms.

A P4.05 output may claim a promoted divergence only when P1.10 itself has produced:

```text
P01-DIVERGENCE-0001
status = promoted
```

The P1.10 policy remains unchanged and requires at least two runtime reproductions, unique run pairs, one contract fingerprint and one divergence signature. Auto-commit remains disabled.

## Reproduction inputs

Each reproduction consists of exactly:

```text
P4.04 A/B session bundle
P1.09 reference manifest
P1.09 probe manifest
reference trace artifact
probe trace artifact
```

The supplied manifests must be the exact files hashed by the P4.04 bundle. The trace files must pass P1.10 artifact-integrity validation against those manifests.

## Independence requirements

P4.05 strengthens the old unique-pair rule. Across reproductions these fields must all be unique:

```text
P4.04 ab_fingerprint
reference.run_id
probe.run_id
reference.capture_fingerprint
probe.capture_fingerprint
```

This prevents one reference or probe observation from being repackaged as multiple reproductions.

## Equality requirements

The reproductions must keep the experiment contract fixed. These P4.04 fields must be identical:

```text
shared_contract
reference.qemu
probe.qemu
reference.machine
probe.machine
```

The `shared_contract` already binds:

```text
pinned Inferno revision
vmapple
4096 MiB RAM
4 vCPUs
P3.06 platform integration fingerprint
P3.06 manifest digest
machine UUID digest
guest input hashes/sizes
trace/debug contract
QEMU version string
```

P4.05 additionally requires the same exact reference QEMU binary digest and the same exact probe QEMU binary digest across the independent reproductions. The reference and probe binaries may still differ from each other, as allowed by P4.04.

## Candidate generation

For every reproduction, P4.05 invokes the existing P1.10 tool:

```text
evidence-bundle.py candidate
```

P1.10 therefore remains responsible for:

```text
P1.09 pair validation
trace artifact integrity
P1.08 parsing/normalization/comparison
earliest mismatch classification
divergence signature generation
runtime-origin validation
promotion eligibility
```

P4.05 rejects a reproduction when P1.10 reports `no_divergence`, non-runtime evidence, or a non-promotable candidate.

## Reproducibility check

Before promotion, all generated candidates must independently agree on:

```text
divergence_signature
contract_fingerprint
```

P4.05 then invokes:

```text
evidence-bundle.py promote
```

with all candidate JSON files. The resulting P1.10 record must be `P01-DIVERGENCE-0001`, `status=promoted`, and `auto_committed=false`.

P4.05 does not reproduce P1.10's internal promotion logic in project-owned code.

## Deterministic orchestration

`.src/.tools/promote-p4.05.sh` evaluates the complete P4.05/P1.10 chain twice using identical inputs and requires the two sanitized P4.05 promotion records to be byte-identical.

Input reproductions are sorted by `ab_fingerprint` before candidate generation, so argument order does not affect the final promotion record.

After deterministic equality is established, the first local candidate set and P1.10 promotion record are published under `.build/p4.05/`.

## Output

The local final descriptor is:

```text
.build/p4.05/promotion.json
```

with classification:

```text
P4_05_REPRODUCIBLE_DIVERGENCE_PROMOTED
```

It binds:

```text
all admitted A/B fingerprints
all independent run IDs
all capture fingerprints
all P1.10 candidate IDs/hashes
one reproduced divergence signature
one P1.09 contract fingerprint
P01-DIVERGENCE-0001 hash/status
```

The descriptor stores no raw local paths, raw UUID or guest input contents.

## Interpretation

A P4.05 promotion means:

```text
same controlled contract
+ independent runtime observations
+ same earliest normalized divergence
+ P1.10 reproduction gate passed
```

It does **not** by itself identify the correct hardware implementation or authorize blindly patching around the mismatch. The promoted divergence becomes evidence for subsequent engineering decisions.
