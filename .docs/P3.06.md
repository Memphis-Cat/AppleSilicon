# P3.06 — Part 03 Integration Gate

Project version: **`3.5.0.0.0.0`**

Status: **Implementation complete — Part 03 closed; real guest/runtime integration remains deferred**

## Objective

Close Part 03 by proving that the five completed VMApple platform contracts form one deterministic, internally consistent machine contract when combined with the closed Part 02 CPU integration state and the Part 01 evidence pipeline.

P3.06 is deliberately an integration gate, not another device-emulation objective.

It must not:

- invent a new Apple device;
- add a speculative `0006` patch;
- silently resolve unknown identity/power/storage/AES semantics;
- substitute a fake GPU for Apple PVG;
- fork a second VMApple runtime launcher;
- treat a source/static pass as a successful macOS boot.

## Integrated layers

P3.06 binds:

```text
Part 01
  P1.07 observational TCG probe
  P1.09 paired evidence manifest contract
  P1.10 divergence promotion gate

Part 02
  P2.06 deterministic CPU integration manifest
  vmapple + TCG + apple-gxf
  max control CPU
  live Apple sysreg policy count = 0

Part 03
  P3.01 ownership inventory
  P3.02 configuration / identity contract
  P3.03 interrupt / timer / power / console contract
  P3.04 boot backdoor / storage contract
  P3.05 PCIe / peripheral / AES / graphics contract
```

The resulting development-side state is one integrated **Apple-compatible virtual-machine contract**, not proof that a particular macOS guest has booted successfully.

## Cross-contract invariants

After the five individual validators pass, P3.06 applies machine-wide checks that must also pass.

### Identity/configuration

P3.02's config-layout discrepancy remains:

```text
unresolved_source_layout_discrepancy
```

with action:

```text
preserve_and_measure_before_any_source_fix
```

P3.06 refuses to close if that discrepancy is silently marked solved.

### Power input

P3.03's PL061/GPIO wiring is integrated, but exact power-button event semantics must remain:

```text
unknown_requires_runtime_evidence
```

Wiring evidence is not converted into a guessed pulse/deassert protocol.

### Pre-boot storage

P3.04 must still report:

```text
BDIF read_supported  = true
BDIF write_supported = false
BDIF write requirement = unknown_requires_runtime_evidence
```

The Apple virtio-block barrier remains:

```text
implementation   = successful_no_op
flush_semantics  = unknown_requires_runtime_evidence
```

P3.06 does not add write or flush semantics without runtime evidence.

### AES

P3.05 must retain the unresolved command set:

```text
DSB
SKG
WRITE_REG
```

and their runtime requirement remains evidence-gated.

The project does not create behavior for those commands merely to improve apparent completeness.

### Graphics

P1.05 remains the graphics portability policy:

```text
apple-gfx-mmio available
    -> instantiate the real Apple PVG-backed QEMU device

apple-gfx-mmio unavailable
    -> warn and continue without PVG
```

P3.06 requires:

```text
fake_gpu_allowed = false
```

and preserves the P3.05 documented guest-support boundary rather than claiming modern macOS graphics compatibility.

As of the P3.06 research pass on 2026-08-11, current QEMU documentation still states that VMApple guest versions newer than macOS 12.x are not supported.

## Machine-wide ownership completion

P3.01 assigned two machine-wide items directly to P3.06:

```text

```

P3.06 closes their **integration ownership**, not their runtime proof.

The memory map remains the pinned VMApple map used by all Part 03 subcontracts.

## Deterministic manifest

The gate produces:

```text
.build/p3.06/platform-integration-manifest.json
```

The manifest records:

- the P2.06 CPU integration fingerprint;
- successful P3.01 through P3.05 validator bindings;
- cross-contract invariants;
- exact patch-series hashes;
- locked evidence/promotion artifacts;
- the integrated VMApple/TCG/apple-gxf machine contract;
- Part 03 closure state.

A canonical JSON representation is hashed into:

```text
platform_integration_fingerprint
```

`prepare-p3.06.sh` creates the manifest twice and requires byte-for-byte equality.

## Preparation pipeline

`.src/.tools/prepare-p3.06.sh` performs:

```text
pinned Inferno source preflight
        |
        v
regenerate P2.06 CPU integration state
        |
        v
validate locked P3.01-P3.05 artifacts
        |
        v
run all five Part 03 contract validators
        |
        v
check cross-contract evidence gates
        |
        v
verify patch series ends at 0005
        |
        v
generate P3.06 manifest twice
        |
        v
byte-identical comparison
        |
        v
P3_06_INTEGRATION_PASS
```

Every meaningful preparation run writes a persistent `.log` under `.logs/`.

No guest is launched by the preparation harness.

## Runtime wrapper

`.src/.tools/run-p3.06-probe.sh` is intentionally a wrapper, not a new VM launch implementation.

It requires a passing P3.06 manifest and the exact P2.06 manifest bound into that result, then delegates:

```text
P3.06
  -> run-p2.06-probe.sh
       -> run-p1.07-probe.sh
```

The runtime result remains observational.

Any meaningful divergence must still flow through:

```text
P1.09 comparable evidence
  -> P1.08 trace comparison
  -> P1.10 promotion gate
```

P3.06 itself cannot promote a crash, warning or changed trace into a compatibility requirement.

## Security and artifact boundaries

P3.06 keeps the existing project rules:

- no Apple proprietary firmware or macOS disk images are committed;
- no real serials, machine identities, private keys, tickets or credentials are committed;
- public AES emulator constants are not treated as authentic Apple secrets;
- no Secure Enclave, Activation Lock, account-security or signing-trust bypass is part of the integration contract.
