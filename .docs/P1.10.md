# P1.10 — Controlled A/B Evidence Bundle and Divergence Promotion Gate

Project version: **`1.0.0.0.0.0`**

Parent: **Part 01 — VMApple Baseline and Host-Dependency Map**

Status: **Implementation complete — real runtime promotion deferred**

Scope: **Final implementation objective of Part 01**

## Objective

P1.10 joins the Part 01 components into one evidence pipeline and defines the only path by which an automatically discovered trace mismatch may become:

```text
P01-DIVERGENCE-0001
```

The goal is not to make a mismatch look important.

The goal is to make it difficult for a false, accidental, synthetic, incomparable, edited, or one-off mismatch to be promoted as the first real AppleSilicon compatibility divergence.

The final Part 01 pipeline is:

```text
P1.09 reference runtime
        ↓
reference manifest + hashed artifacts

P1.07 probe runtime
        ↓
P1.10 post-run probe collector
        ↓
probe manifest + hashed artifacts

reference + probe
        ↓
P1.09 pairing contract
        ↓
artifact-integrity verification
        ↓
P1.08 normalization/comparison
        ↓
P01-DIVERGENCE-CANDIDATE
        ↓
repeat with independent run pair
        ↓
same contract + same divergence signature
        ↓
P01-DIVERGENCE-0001
```

No real VM is launched by the P1.10 preparation/self-check path.

## Why P1.10 is the final Part 01 objective

Part 01 was created to discover the first precise compatibility difference between the known VMApple/HVF reference path and the controlled non-host TCG path.

P1.01 through P1.09 already provide:

```text

```

P1.10 supplies the missing integration and promotion boundary.

Adding more P1.xx objectives after this point would move implementation work that belongs to the first discovered compatibility contract back into the baseline part. Part 01 therefore closes at P1.10.

## Primary reference behavior

QEMU documents `vmapple` as its implementation of the virtual device model used by Apple's Virtualization.framework for Apple Silicon macOS guests.

Primary source:

- <https://www.qemu.org/docs/master/system/arm/vmapple.html>

QEMU's tracing documentation describes trace-event files, the default log tracing backend, and preservation of guest-operation data in trace events.

Primary source:

- <https://www.qemu.org/docs/master/devel/tracing.html>

P1.10 does not define a new trace format. It consumes the P1.08/P1.09 evidence contracts already built around those QEMU mechanisms.

## Candidate versus confirmed divergence

One successful A/B comparison can create:

```text
P01-DIVERGENCE-CANDIDATE
```

It cannot create:

```text
P01-DIVERGENCE-0001
```

A candidate records:

```text
reference run id
probe run id
reference/probe manifest digests
reference/probe trace digests
P1.09 contract fingerprint
P1.08 first mismatch
classification
divergence signature
runtime/non-runtime origin
promotion eligibility
```

If the two normalized event streams are equal, the bundle is recorded as:

```text
no_divergence
```

and is not promotion eligible.

## Artifact-integrity gate

P1.10 does not accept an arbitrary text file merely because the caller labels it a trace.

Before comparison, the supplied reference and probe trace files are SHA-256 hashed.

Each must match an artifact recorded in its own P1.09 manifest using an allowed trace artifact kind:

```text
serial_log
normalized_trace
```

The digest and byte count must match.

Therefore an edited, replaced, unrelated, or unrecorded trace cannot silently participate in the promotion pipeline.

## P1.09 comparability gate

Before P1.08 comparison, P1.10 invokes the P1.09 pairing contract.

The A/B pair must still match on the fields P1.09 declared equal, including:

```text
pinned source revision
VMApple machine type
RAM
SMP
trace event set
debug set
firmware digest/size
auxiliary-storage digest/size
disk digest/size
machine-identity digest/size
hardware-model digest metadata
```

The intended differences remain:

```text
reference:
    accelerator = hvf
    cpu         = host

probe:
    accelerator = tcg
    cpu         = max | apple-gxf
```

If the P1.09 contract fails, P1.10 refuses comparison/promotion.

## Divergence signature

P1.10 derives a stable SHA-256 signature from the earliest normalized mismatch:

```text
classification
canonical reference event
canonical probe event
bounded-resynchronization anchor, when present
```

Example conceptual material:

```text
classification = mmio_value_divergence
reference      = memory_region_ops_read cpu=0 addr=0x... value=0x... size=... name='...'
probe          = memory_region_ops_read cpu=0 addr=0x... value=0x... size=... name='...'
anchor         = ...
```

The signature does not include host timestamps or host pointer addresses because P1.08 already removes that non-semantic noise.

It does include guest-visible addresses/values and event semantics.

## Contract fingerprint

P1.10 separately creates a SHA-256 fingerprint over the entire P1.09 pair-equality contract.

Two candidate runs can be treated as reproductions only when they have the same contract fingerprint.

This prevents a result from being called reproducible if, for example, the second run silently used:

```text
different firmware
different disk
different machine identity
different RAM/SMP
different trace set
different pinned emulator revision
```

## Runtime-origin gate

Synthetic and documentation fixtures remain useful for development validation but cannot become real evidence.

The promotion policy rejects run results containing markers such as:

```text
synthetic
fixture
example
self-check
unverified
not-run
not_started
```

Reference evidence is considered runtime evidence only when its result uses the P1.09 runtime family:

```text
P1_09_REFERENCE_...
```

Probe evidence is considered runtime evidence only when its result uses a controlled runtime family:

```text
P1_07_PROBE_...
P1_10_PROBE_...
```

A non-runtime bundle can still prove that the tooling works, but its candidate has:

```text
promotion_eligible = false
```

## Reproduction gate

P1.10 requires at least:

```text
2 independent A/B run pairs
```

before promotion.

The two candidate bundles must have:

```text
unique reference/probe run pairs
same P1.09 contract fingerprint
same divergence signature
runtime evidence origin
promotion_eligible = true
```

Reusing the same A/B run pair twice is rejected.

A second run that diverges differently is not considered reproduction of the first result.

## Promotion output

After all gates pass, P1.10 may create local files:

```text
P01-DIVERGENCE-0001.json
P01-DIVERGENCE-0001.md
```

The record includes:

```text
promotion id
reproduction count
classification
divergence signature
contract fingerprint
reference behavior
probe behavior
candidate/run identifiers
manifest hashes
trace hashes
```

The current MMIO trace contract does not contain a guest PC for every event.

Therefore P1.10 writes:

```text
PC: unknown from current MMIO trace contract
```

rather than inventing an instruction address.

A later focused tracing objective may add PC/instruction evidence if the specific divergence requires it.

## No automatic GitHub promotion

The promotion policy has:

```text
auto_commit_promotion = false
```

Passing the gate creates a local evidence record only.

The tool does not:

```text
commit the record
push to GitHub
modify the root README
patch XNU
patch firmware
patch around the mismatch
```

The first implementation part after Part 01 must explain the hardware contract behind the promoted divergence.

## Probe manifest completion

P1.07 deliberately focused on capturing the TCG runtime evidence and did not originally produce the P1.09 manifest introduced later.

P1.10 adds:

```text
.src/.tools/collect-p1.10-probe.sh
```

This is a post-run collector.

It does **not** launch QEMU.

It accepts an already completed P1.07 launcher log and:

1. extracts its start/end time,
2. extracts the runtime classification,
3. verifies the result belongs to `P1_07_PROBE_*`,
4. verifies TCG + `max|apple-gxf`,
5. extracts RAM/SMP/debug configuration,
6. finds the serial/QEMU/trace-capability logs recorded by the launcher,
7. requires the collector to run on the same OS/architecture as the recorded probe,
8. hashes the local firmware/aux/disk/machine-identity inputs,
9. hashes the P1.07 artifacts,
10. invokes the P1.09 manifest collector with `role=probe`,
11. validates the generated manifest.

The machine-identity and optional hardware-model inputs remain local and are represented by digest metadata only.

## Evidence bundle tool

P1.10 adds:

```text
.src/.tools/evidence-bundle.py
```

Commands:

```text
candidate
promote
self-check
```

### candidate

Inputs:

```text
reference manifest
probe manifest
reference trace artifact
probe trace artifact
```

Outputs under a caller-selected local directory:

```text
normalized-reference.log
normalized-probe.log
pair-report.json
candidate.json
P01-divergence-candidate.md
```

The command first performs P1.09 pairing and artifact-integrity validation, then runs the P1.08 comparison.

### promote

Inputs:

```text
2 or more candidate.json files
```

The command refuses promotion unless every reproduction gate passes.

Successful local output:

```text
P01-DIVERGENCE-0001.json
P01-DIVERGENCE-0001.md
```

### self-check

The self-check uses the existing sanitized P1.08 fixtures and P1.09 examples to prove:

```text
matching manifests can be paired
recorded trace hashes are enforced
real guest-value difference creates a candidate
semantically equivalent traces produce no divergence
synthetic candidate is never promotion eligible
one candidate cannot pass reproduction minimum
two matching internal test candidates satisfy promotion logic
mismatched divergence signatures are rejected
```

The positive internal promotion check exists only inside the self-check process. It does not write a runtime-promotable candidate file.

## Acceptance conditions

P1.10 implementation is complete when:

1. one A/B pair can produce a deterministic candidate bundle,
2. P1.09 comparability is required before trace comparison,
3. supplied trace files must match hashes in their manifests,
4. synthetic/example/self-check evidence is barred from promotion,
5. no-divergence results cannot be promoted,
6. a stable divergence signature is generated from the earliest normalized mismatch,
7. a stable contract fingerprint is generated from P1.09 equality fields,
8. at least two unique runtime A/B run pairs are required,
9. reproductions must share the same contract fingerprint,
10. reproductions must share the same divergence signature,
11. a successful gate creates a local `P01-DIVERGENCE-0001` record,
12. promotion is never automatically committed,
13. the existing P1.07 probe result can be converted into a P1.09 probe manifest without rerunning QEMU,
14. deterministic development self-checks require no guest execution,
15. every preparation/collection execution leaves a `.log`.
