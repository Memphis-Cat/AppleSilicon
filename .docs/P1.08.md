# P1.08 — VMApple Trace Normalization and Earliest-Divergence Extraction

Project version: **`0.8.0.0.0.0`**

Parent: **Part 01 — VMApple Baseline and Host-Dependency Map**

Status: **Implementation complete — real runtime trace comparison intentionally deferred**

## Objective

P1.08 turns the raw evidence produced by P1.07 into a deterministic comparison format.

The narrow question is:

> What is the earliest guest-visible behavior that differs between a reference VMApple run and the controlled non-host TCG run?

The intended future comparison is:

```text
A — Apple/HVF VMApple reference trace
B — VMApple + TCG + explicit max/apple-gxf probe trace
```

P1.08 implements the analysis layer now. The project owner is not required to collect either runtime trace until the final integration testing stage.

## Verified trace contract

The project is pinned to:

```text
ChefKissInc/Inferno
cc4302a99167abec69b714cfd00c38caece7e7de
```

Its `system/trace-events` defines:

```text
memory_region_ops_read(
    int cpu_index,
    void *mr,
    uint64_t addr,
    uint64_t value,
    unsigned size,
    const char *name
)

memory_region_ops_write(... same fields ...)
```

The formatted trace contains:

```text
cpu
mr
addr
value
size
name
```

That matches the current upstream QEMU MMIO trace contract and gives P1.08 a precise normalization boundary.

Primary sources:

- pinned Inferno `system/trace-events`
- upstream QEMU `system/trace-events`
- <https://www.qemu.org/docs/master/devel/tracing.html>

## Conservative normalization policy

P1.08 normalizes away only values that are host/runtime noise for these events:

```text
QEMU thread/PID and timestamp prefix
MemoryRegion host pointer (`mr`)
hexadecimal letter case
irrelevant hexadecimal leading zeroes
```

It preserves:

```text
event type
guest CPU index
guest MMIO address
value
access size
memory-region name
record ordering
original source line number
original raw record
```

Guest addresses and values are never converted to placeholders. They can be the compatibility failure we need to discover.

## Canonical format

Raw:

```text
719585@1608130130.441188:memory_region_ops_read cpu 0 mr 0x562fdfbb3820 addr 0x000003CC value 0x00000067 size 1 name 'vmapple-cfg'
```

Canonical:

```text
memory_region_ops_read cpu=0 addr=0x3cc value=0x67 size=1 name='vmapple-cfg'
```

A second run may use a completely different host pointer and timestamp and still compare equal when the guest-visible operation is identical.

## Comparator commands

Normalize one mixed trace/serial log:

```bash
.src/.tools/compare-boot-traces.py normalize input.log \
  --output normalized.log
```

Compare two traces:

```bash
.src/.tools/compare-boot-traces.py compare reference.log probe.log \
  --normalized-reference normalized-reference.log \
  --normalized-probe normalized-probe.log \
  --report-md P01-divergence-candidate.md \
  --report-json P01-divergence-candidate.json
```

Run the embedded synthetic checks:

```bash
.src/.tools/compare-boot-traces.py self-check
```

The implementation uses only Python's standard library.

## Input behavior

P1.08 accepts mixed text logs. It extracts only events listed in `p1.08-compare.json`; unrelated serial output is ignored by the canonical event stream and remains preserved in the original raw log.

For P1.07, QEMU trace output is captured into the serial/stderr evidence stream, so that file becomes a valid P1.08 input without rewriting the runtime harness.

## Divergence classifications

The current comparator can classify the first mismatch as:

```text
mmio_value_divergence
mmio_address_divergence
mmio_size_divergence
mmio_region_divergence
cpu_divergence
event_divergence
sequence_divergence
trace_length_divergence
unstructured_payload_divergence
```

A mismatch is reported rather than patched away.

## Bounded resynchronization

A simple first-difference comparator can misdescribe insertion/deletion cases.

Example:

```text
reference: A B C D
probe:     A B X C D
```

P1.08 therefore searches only within the configured bounded window for the next identical event. The default is:

```text
32 events
```

The mismatch remains recorded. The later matching event is attached only as a resynchronization anchor.

The comparator never performs unlimited skipping in order to make two traces look equal.

## Reports

A real comparison can produce:

```text
normalized-reference.log
normalized-probe.log
P01-divergence-candidate.md
P01-divergence-candidate.json
```

The machine-readable report includes:

```text
source paths
event counts
ignored-line counts
first classification
event indexes
source line numbers
raw records
canonical records
context window
bounded resynchronization result
```

A generated report remains **P01-DIVERGENCE-CANDIDATE** until a real runtime result has been reproduced and reviewed.

P1.08 intentionally does not automatically assign `P01-DIVERGENCE-0001`.

## Development-side validation design

`prepare-p1.08.sh` creates a mandatory `.log` and performs:

1. JSON configuration validation.
2. Python syntax compilation of `compare-boot-traces.py`.
3. The comparator's embedded self-check.
4. Comparison of the reference and equivalent fixtures, which must report no divergence.
5. Byte-for-byte comparison of the two normalized equivalent outputs.
6. Comparison of the changed-value fixture, which must return `mmio_value_divergence` at event index 1.
7. Comparison of the insertion fixture, which must return `sequence_divergence` and a bounded resynchronization of reference skip 0 / probe skip 1.

The harness writes its generated artifacts under:

```text
.build/.p1.08/.self-check/
```

and its persistent execution record under:

```text
.logs/AppleSilicon-p1.08-prepare-*.log
```

No QEMU instance or macOS guest is launched by this validation harness.

## Security and privacy

P1.08 does not store proprietary firmware, disks, UUIDs, Apple account material, credentials, signing tickets, private keys, or machine secrets.

Real trace/log artifacts remain in ignored local artifact directories unless deliberately sanitized before inclusion in the repository.
