# P1.08 — VMApple Trace Normalization and Earliest-Divergence Extraction

Project version: **`0.8.0.0.0.0`**

Parent: **Part 01 — VMApple Baseline and Host-Dependency Map**

Status: **Implementation in progress — runtime trace comparison intentionally deferred**

## Objective

P1.08 turns the raw evidence produced by P1.07 into a deterministic comparison format.

The objective is not to guess why macOS fails. It is to answer a narrower question first:

> What is the earliest guest-visible behavior that differs between a reference VMApple run and the controlled non-host TCG run?

The intended comparison is:

```text
A — reference VMApple trace
    Apple/HVF reference path when available

B — probe VMApple trace
    TCG + explicit max or apple-gxf CPU
```

P1.08 must identify the first meaningful divergence without requiring manual inspection of megabytes of timestamped trace output.

The project owner is not required to run P1.08. Runtime trace comparison remains deferred under the project-wide final-testing rule.

## Primary source research

### QEMU trace output

QEMU's tracing documentation shows the default log backend emitting records in this shape:

```text
719585@1608130130.441188:memory_region_ops_read cpu 0 mr 0x562fdfbb3820 addr 0x3cc value 0x67 size 1
```

The prefix contains host/runtime information. The trace event itself contains the guest interaction.

QEMU also documents that the log backend writes trace events directly to standard error and that `-msg timestamp=on|off` controls the thread/timestamp prefix.

Primary source:

- https://www.qemu.org/docs/master/devel/tracing.html

### Current MMIO trace contract

Current QEMU declares the MMIO events as:

```text
memory_region_ops_read(
    int cpu_index,
    void *mr,
    uint64_t addr,
    uint64_t value,
    unsigned size,
    const char *name
)

memory_region_ops_write(... same fields ...)
```

The formatted record contains:

```text
cpu
mr
addr
value
size
name
```

Primary source:

- `qemu/qemu`, `system/trace-events`

This distinction determines what P1.08 is allowed to normalize.

## Noise versus evidence

P1.08 uses a deliberately conservative normalization policy.

### Normalize away

The following values are host/runtime noise for the current MMIO comparison:

```text
QEMU trace thread/PID prefix
QEMU trace timestamp prefix
MemoryRegion host pointer (`mr`)
hexadecimal letter case
irrelevant leading zeroes in hexadecimal numbers
```

The `mr` pointer is a host virtual address. For the current MMIO event, QEMU also provides the memory-region `name`, so keeping the raw host pointer would add address-space-layout noise without adding guest behavior information.

### Preserve exactly as semantic data

P1.08 must preserve:

```text
event type (read/write)
guest CPU index
guest MMIO address
value
access size
memory-region name
record ordering
```

In particular, **guest addresses and values must never be normalized into placeholders**. Those are often the incompatibility we are trying to find.

## Canonical MMIO format

Raw:

```text
719585@1608130130.441188:memory_region_ops_read cpu 0 mr 0x562fdfbb3820 addr 0x000003cc value 0x00000067 size 1 name 'vmapple-cfg'
```

Canonical:

```text
memory_region_ops_read cpu=0 addr=0x3cc value=0x67 size=1 name='vmapple-cfg'
```

A second run with a different timestamp and host `mr` pointer must normalize to the same line if its guest behavior is the same.

## Input policy

P1.08 accepts text logs.

The first supported source is the P1.07 serial/stderr log because QEMU's default `log` tracing backend writes trace events to stderr and P1.07 captures that stream persistently.

Non-trace serial text is ignored by default during trace comparison. It remains available in the original P1.07 log for later contextual inspection.

The normalizer is intentionally versioned around known trace events rather than applying broad regular expressions to every hexadecimal value in every line.

## Comparator behavior

The comparator walks the two canonical event streams from the beginning.

When records are equal, it advances both streams.

At the first mismatch it records:

```text
reference event index
probe event index
original source line numbers
canonical reference event
canonical probe event
classification
context before/after
possible resynchronization anchor
```

### Initial classifications

```text
mmio_value_divergence
mmio_address_divergence
mmio_size_divergence
mmio_region_divergence
cpu_divergence
event_divergence
sequence_divergence
trace_length_divergence
unstructured_payload_divergence
```

A difference is reported; it is not silently patched around.

## Bounded resynchronization

Two traces can contain an inserted/missing event before returning to the same sequence.

P1.08 therefore performs a bounded look-ahead after the first mismatch. The default window is intentionally small.

Example:

```text
reference: A B C D
probe:     A B X C D
```

The comparator reports the divergence at `X`, but also records `C` as a resynchronization anchor.

This improves diagnosis without deleting the divergence.

The comparator must never skip an unlimited number of events merely to make two traces appear equal.

## Output

A comparison produces:

```text
normalized-reference.log
normalized-probe.log
P01-divergence-candidate.md
P01-divergence-candidate.json
```

The report uses the word **candidate** until a real runtime result is reproduced and reviewed.

P1.08 does not automatically assign `P01-DIVERGENCE-0001`; that identifier is reserved for the first confirmed compatibility divergence.

## Determinism requirements

For identical input files and configuration, the tool must produce identical canonical event sequences and equivalent JSON content.

The comparison implementation must use only Python's standard library for P1.08 so the analysis step does not introduce another package-management dependency.

## Security and privacy

P1.08 must not copy proprietary firmware, disks, UUIDs, Apple account material, credentials, tickets, private keys, or machine secrets into the repository.

Trace/log files generated from real experiments remain under `.logs/` or another ignored local artifact location unless a deliberately sanitized fixture is created.

## Implementation files

P1.08 introduces:

```text
.src/.configs/p1.08-compare.json
.src/.tools/compare-boot-traces.py
.src/.tools/prepare-p1.08.sh
```

`compare-boot-traces.py` provides normalization, comparison, machine-readable reporting, human-readable reporting, and an embedded self-check.

`prepare-p1.08.sh` performs development-side validation and writes a mandatory `.log`, but does not launch QEMU or macOS.

## Acceptance conditions

P1.08 implementation is complete when:

1. QEMU MMIO trace prefixes can be removed deterministically.
2. Host `mr` pointers do not cause false differences.
3. Guest CPU/address/value/size/region information remains intact.
4. Two semantically equal synthetic traces normalize identically despite different timestamps and host pointers.
5. A synthetic changed MMIO value is detected at the correct first event.
6. A bounded resynchronization anchor can be reported for insertion/deletion cases.
7. Human-readable and JSON reports are produced.
8. The preparation/self-check path produces a persistent `.log`.
9. No real guest run is required from the project owner.

## Not completed by P1.08

P1.08 does not:

- prove a real macOS divergence yet,
- infer Apple CPU semantics from a mismatch,
- emulate an Apple system register,
- alter XNU,
- alter Apple firmware,
- remove a mismatch merely because it is inconvenient,
- replace the original raw logs.
