# P3.01 — Platform Contract Inventory and Ownership Map

Project version: **`3.0.0.0.0.0`**

Status: **Implementation complete — static ownership map**

## Objective

P3.01 establishes the non-CPU VMApple platform inventory before Part 03 starts changing behavior.

The objective is:

> Identify every major guest-visible platform component, record where its behavior currently comes from, assign one later objective as its owner, and refuse to infer implementation work solely from the component being Apple-specific.

Part 02 remains the owner of CPU features and Apple implementation-defined CPU system registers.

## VMApple is a hybrid machine

Pinned Inferno's VMApple Kconfig selects ordinary QEMU infrastructure including:

```text
ARM_GICV3
PCI_EXPRESS
PCI_EXPRESS_GENERIC_BRIDGE
PL011
PL031
PL061
GPIO_PWR
PVPANIC_MMIO
```

It also selects VMApple-specific devices:

```text
VMAPPLE_AES
VMAPPLE_BDIF
VMAPPLE_CFG
VMAPPLE_VIRTIO_BLK
```

and the Apple PVG MMIO graphics path.

This means the correct engineering question is not "what Apple hardware must we rewrite?" but "which part of the existing virtual machine contract is actually divergent under TCG?"

## Guest-visible anchors

XNU's VMApple configuration explicitly identifies:

```text
VMAPPLE
APPLEVIRTUALPLATFORM
HAS_GIC_V3
PL011_UART
```

That gives direct guest-side evidence for the virtual-platform identity, GICv3 and PL011 console contracts.

Other components are tracked using the reference machine/device model without promoting them to boot-critical status merely because they are present.

## Ownership classes

P3.01 uses:

```text
generic_qemu
vmapple_specific
host_framework_dependent
unknown_requires_evidence
```

### Generic QEMU examples

```text
GICv3
architectural virtual timer
PL011 UART
PL031 RTC
PL061 GPIO
pvpanic
PCIe/GPEX
XHCI
virtio-net
```

These are preserved until evidence demonstrates a VMApple-specific incompatibility.

### VMApple-specific examples

```text
configuration region
BDIF pre-boot storage backdoor
VMApple virtio-blk extensions
VMApple AES
machine memory/IRQ layout
```

Their presence is known, but exact semantic changes require evidence.

### Host-framework-dependent example

```text
apple-gfx-mmio / Apple PVG
```

P1.05 already made this path optional when unavailable. P3.01 therefore records it as a separate ownership class instead of pretending graphics must be reimplemented before early boot work.

### Unknown/evidence-gated example

The pre-boot firmware window is implemented by QEMU, but the reference pre-boot binary remains an external local input. P3.01 records that boundary without redistributing or reverse-engineering proprietary material.

## Machine-readable contract

P3.01 adds:

```text
.src/.configs/p3.01-platform-contract.json
```

Each component records:

```text
id
category
ownership
project_owner
runtime_requirement
baseline_state
evidence
action
notes
```

Allowed actions are intentionally limited to:

```text
preserve
validate
investigate
defer
```

There is no automatic `implement` action in P3.01.

## Objective ownership

The inventory routes components forward as follows:

```text
P3.02 -> configuration + platform identity
P3.03 -> IRQ + timers + console + power/diagnostics
P3.04 -> boot backdoor + storage
P3.05 -> PCIe + peripherals + AES + graphics
P3.06 -> machine-wide integration/layout gate
```

## Validation tooling

P3.01 adds:

```text
.src/.tools/platform-contract.py
.src/.tools/prepare-p3.01.sh
```

`platform-contract.py` supports:

```text
validate
summary
lookup
self-check
```

The validator rejects:

```text
duplicate component IDs
unknown ownership classes
automatic "implement" actions
Inferno/XNU source-lock drift
CPU ownership moving out of Part 02
P3.07 scope creep
disabled evidence gates
generic-QEMU components pre-classified for replacement
```

The logged preparation harness verifies the exact Inferno revision and Git blob IDs, checks representative VMApple source invariants, runs contract self-checks and writes a deterministic summary to:

```text
.build/p3.01/platform-contract-summary.json
```

Every preparation run also writes:

```text
.logs/AppleSilicon-p3.01-YYYYMMDD-HHMMSS-PID.log
```

## What P3.01 proves

P3.01 proves that Part 03 has a bounded and reviewable ownership map.

It does **not** prove:

- that every reference device is required for macOS boot;
- that every generic QEMU device already behaves perfectly for VMApple;
- that Apple AES or PVG is boot-critical;
- that the configuration-region default strings are correct;
- that the external pre-boot environment can be replaced;
- that macOS boots under TCG.
