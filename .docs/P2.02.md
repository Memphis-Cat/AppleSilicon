# P2.02 — Apple System Register Emulation Framework

Project version: **`2.1.0.0.0.0`**

Status: **Implementation complete — framework only**

## Objective

P2.02 creates the project-owned bridge between the P2.01 Apple CPU register inventory and Inferno/QEMU's existing AArch64 system-register machinery.

The objective is intentionally narrow:

> Provide a real place to register Apple implementation-defined AArch64 system registers under TCG without assigning behavior that has not yet been justified by evidence.

P2.02 does **not** decide what HID, GXF, SPRR, AMX, timer aliases, Apple pointer-authentication controls, or other inventory registers return or store.

Those semantics belong to P2.03.

## Upstream behavior used

Pinned Inferno already contains an Apple-oriented CPU model:

```text
-cpu apple-gxf
```

Its initializer is:

```c
static void aarch64_apple_gxf_initfn(Object *obj)
```

and it is built on top of Inferno's `max` AArch64 CPU model.

This gives AppleSilicon a scoped integration point: Apple compatibility code can attach to `apple-gxf` without contaminating normal `max`, Cortex, Neoverse, KVM, or HVF CPU behavior.

QEMU/Inferno already implements AArch64 system-register decoding through `ARMCPRegInfo` and `define_one_arm_cp_reg()`. P2.02 therefore does not add a second MRS/MSR decoder.

## AppleSysRegSpec

The new framework defines an encoding-only structure:

```c
typedef struct AppleSysRegSpec {
    const char *name;
    uint8_t op0;
    uint8_t op1;
    uint8_t crn;
    uint8_t crm;
    uint8_t op2;
} AppleSysRegSpec;
```

This deliberately mirrors the useful part of P2.01's machine-readable register inventory.

It does **not** contain:

```text
reset value
stored value
constant value
read policy
write policy
runtime-required flag
VMApple-required flag
```

because adding those fields with guessed values would silently turn an inventory into a fake hardware model.

## QEMU cpreg bridge

P2.02 adds:

```c
apple_sysreg_register_undefined(...)
```

This converts one validated `AppleSysRegSpec` into an `ARMCPRegInfo` and registers it through:

```c
define_one_arm_cp_reg(cpu, &ri);
```

The helper is deliberately fail-closed.

Its `ARMCPRegInfo` uses:

```text
ARM_CP_STATE_AA64
ARM_CP_NO_RAW
ARM_CP_NO_GDB
CP_ACCESS_UNDEFINED
```

The broad `PL0_RW` access mask does not grant guest access: it ensures accesses reach the explicit access callback, which always returns `CP_ACCESS_UNDEFINED`. The read/write callbacks are unreachable assertions so an accidental future policy bug cannot silently turn an undefined register into zero-backed state.

## Why undefined instead of zero

The easiest fake implementation would be:

```text
read -> 0
write -> ignore
```

That is not acceptable for an unknown Apple register.

A zero value may mean a feature is disabled, a lock is clear, a timer is stopped, a permission is absent, or a hardware state is valid. Returning zero without evidence can move XNU farther into boot while making the model less correct.

Therefore P2.02 treats unknown behavior as unknown.

The framework has support for an explicit undefined registration because undefined access is a safe diagnostic policy when we know the encoding but do not know the semantics.

## Default policy count is zero

Most importantly, P2.02 does **not** register the 74 P2.01 inventory entries automatically.

The default framework initialization contains no call that installs a guest-visible Apple sysreg policy.

This preserves the distinction:

```text
known Apple register encoding
!=
proven VMApple requirement
```

P2.03 will be the first objective allowed to install an evidence-backed policy table.

## TCG-only integration

The framework is wired to `apple-gxf` only inside the existing:

```c
if (tcg_enabled()) {
    ...
}
```

block.

The resulting structure is:

```text
apple-gxf CPU init
    |
    +-- max CPU initialization
    +-- existing Apple GXF / PAUTH setup
    +-- TCG only
           |
           +-- apple_sysreg_framework_init(cpu)
```

P2.02 therefore does not alter the `host` CPU path, KVM host feature discovery, or HVF host feature discovery.

## Build integration

`target/arm/meson.build` adds:

```text
apple-sysregs.c
```

only to the existing `TARGET_AARCH64` source set.

No new instruction translator or accelerator backend is introduced.

## Development-side validation

P2.02 adds:

```text
.src/.tools/prepare-p2.02.sh
```

The harness:

1. validates the P2.01 contract;
2. verifies the exact pinned Inferno revision;
3. refuses tracked modifications in the upstream submodule;
4. creates a disposable `.build/p2.02/inferno-src` tree;
5. applies patches `0001`, `0002`, and `0003` in order with `git apply --check` first;
6. verifies the new C/header files exist;
7. verifies Meson compiles the framework;
8. verifies `apple-gxf` attaches the framework only in its TCG block;
9. verifies the cpreg bridge uses `CP_ACCESS_UNDEFINED`;
10. verifies no read-as-zero, write-ignore, constant, or reset policy leaked into P2.02;
11. verifies the default guest-visible policy count remains zero;
12. runs `git diff --check` on the prepared source.

Every execution writes a `.log` artifact.

No macOS guest is launched by this harness.

## What P2.02 proves

P2.02 proves that the project now has a defined source-level route from:

```text
Apple register encoding
        |
        v
AppleSysRegSpec
        |
        v
ARMCPRegInfo
        |
        v
QEMU AArch64 cpreg registration
```

and that this route is scoped to the Apple-oriented TCG CPU model.

It does **not** prove that any particular Apple register is needed by VMApple or that macOS boots farther.

## Guest status

No guest execution is claimed for P2.02.

The project owner's testing policy remains unchanged: real macOS/HVF/TCG integration testing is deferred until the finished integration stage.

## Exit criteria

P2.02 is implementation-complete when:

- the framework has its own C/header source;
- it uses QEMU's real cpreg infrastructure;
- it is compiled for AArch64;
- it is attached only to the TCG `apple-gxf` path;
- its explicit unknown path is fail-closed;
- no unknown value/reset/access semantics are invented;
- default guest-visible policy count is zero;
- the patch series can be validated in a disposable source tree;
- the validation path emits a `.log`.

These conditions are implemented by the P2.02 patch and preparation harness.
